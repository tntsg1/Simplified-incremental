# 《星际拓荒者 / Stellar Ascension》游戏设计稿（重设计版）

> **一句话**：亲手建立第一座星际殖民地，找出产能瓶颈，再把成熟的工作交给自动化；你的决策范围从一颗星球扩大到多个星系和银河。

## 1. 游戏承诺

- **类型与平台**：PC、Godot、2D 轻建造与策略增量游戏。单人、买断制，不使用体力、抽卡或强制等待付费。
- **主线目标**：约 12—16 小时完成三座银河的远征；实际时长以试玩数据调整。通关后可继续扩张，没有重置或声望转生。
- **主要乐趣**：发现瓶颈、选择新目标、看到产量和版图增长、把重复操作变为自动运行。
- **目标玩家**：喜欢增量成长与地图探索，愿意做轻量产能规划，但不想管理传送带、人口和复杂配方的玩家。
- **30 秒体验**：点选矿点 → 放置矿机 → 矿机开始运转 → 产量数字上涨 → 界面指出下一个可改善的瓶颈。

核心循环：**观察瓶颈 → 比较两个可行投资 → 建设或探索 → 看见产能与地图变化 → 自动化已掌握的工作 → 面对更大范围的新瓶颈**。每次解锁应改变玩家能作出的决定，而不只是给现有数字乘一个系数。

## 2. 三个尺度与玩家的工作

| 尺度 | 玩家在这里做什么 | 何时逐渐放手 |
| --- | --- | --- |
| 星球地表 | 选择矿点、放置少量建筑、确定星球专精 | 保存建设蓝图后，由星球自动排队建设 |
| 恒星系 | 选择殖民目标、查看能源容量和运输、处理系统瓶颈 | 多数星球完成蓝图，运输自动平衡 |
| 银河 | 探索航线、决定扩张顺序、分配跨银河支援 | 旧银河在后台持续生产和运输 |

滚轮缩放与面包屑导航连接三个独立场景。切换时保留镜头方向和焦点，并用 0.25—0.4 秒过渡；不做一张无限大场景。选中对象在缩放后仍保持选中，避免玩家迷路。

## 3. 经济规则：四种资源，四种作用

| 资源 | 产生方式 | 所在范围 | 主要用途与消耗 |
| --- | --- | --- | --- |
| **Minerals 矿物** | 占据矿点的矿机 | 每颗星球独立库存；通过船只运输 | 建筑、升级、殖民船、轨道设施的建造成本 |
| **Energy 能源容量** | 发电建筑提供 | 同一恒星系共享 | 建筑占用容量；供给不足时，该系统生产效率按 `供给/需求` 降低 |
| **Science 科研点** | 科研建筑产生 | 全帝国共享 | 科技解锁与高级自动化研究；研究时一次性消耗 |
| **Credits 信用点** | 殖民中心与商业建筑产生 | 全帝国共享 | 建造、升级、殖民与科技的另一项一次性成本 |

普通建筑没有每秒维护费。产量建筑只需满足能源容量；能源既不是可囤积货币，也不随时间扣除。矿物无仓储上限，离线生产不会因仓满而白白损失。所有费用、产量和所需能源在确认建造前显示。

**避免一种升级统治全局**：同类建筑每升一级，产量约乘以 1.6，升级成本约乘以 2.2。具体值由试玩校准。矿点数量限制每颗星球可建的矿机，矿点本身永不枯竭。当本地升级的边际收益低于开发新矿点时，扩张就有明确价值。升级与扩张都应在界面上显示“新增产量／成本／预计回本时间”，供玩家自行选择。

## 4. 让探索产生真正不同的选择

每颗星球只有一种清楚可见的**专长**，例如矿机产量 +25%、发电效率 +30%、科研产量 +20% 或商业收入 +25%。专长没有生存惩罚；所有星球都能殖民。星球外观可以是沙漠、海洋、冰冻、火山等，外观不暗藏额外规则。

银河图采用带保底的半随机航线。每次从已知边界出发，至少有两个可探索方向；扫描结果提前显示星球数量、矿点总量和已知专长。玩家通常能在“近但普通”“远但高价值”之间选择。关键剧情节点固定，地图生成后校验连通性和资源供给，不能生成死局。

**矿点稀缺，矿物不枯竭。** 后期仍能强化旧星球，但新的矿点、专长和更短的航线让新区域具有独立价值。稀有天体首先提供视觉惊喜，可附带一项小而透明的加成；不增设第五种核心资源。

## 5. 地表建设：少量布局，快速反馈

地表是小型 2D 等距地图。建筑吸附到隐形网格，放下前显示占地、效果、费用和当前能否供电。普通星球约 8—14 个可用矿点、20—35 个主要建筑位置；手动开发一颗星球的理想时长是 5—10 分钟，不应让玩家把同一套动作重复几十次。

首版的核心建筑共八种：

| 建筑 | 明确作用 |
| --- | --- |
| 殖民中心 | 建立殖民地，提供少量信用点；首个中心由殖民船自动放置 |
| 矿机 | 占据一个矿点，生产矿物 |
| 太阳能阵列 | 廉价能源容量 |
| 聚变堆 | 昂贵但高密度的能源容量 |
| 科研站 | 生产科研点 |
| 商业中心 | 生产信用点 |
| 太空港 | 接入系统内自动运输网络，允许殖民船出发 |
| 太空电梯 | 开启星球蓝图、自动建设与升级，是殖民地成熟标志 |

普通建筑可拆除并返还其建造与升级所花的矿物和信用点；已经获得的产出不会倒扣，已完成的科技费用也不会返还。拆除正在生产的建筑会立即停止产出。此规则让布局试错轻松，也不会让重复拆建本身产生资源。

**不设必拉物流线。** 玩家可以在地表选择两座建筑，创建一条纯视觉的光流连线；它不影响产能、运输或能源，默认不进入新手教程。建筑动画、货运船和地图点亮承担主要“文明正在运行”的视觉反馈。

## 6. 运输：真实到达，自动调度

矿物在本地库存中，不能隔空建造。殖民船抵达时携带一笔明确显示的启动矿物，保证新星球能建第一批设施。两颗星球都有太空港后，系统自动建立运输任务：优先满足建设队列和殖民船订单，再给低库存星球补足目标储备。玩家可以调整目标储备或暂停某条航线，但不必手动配船或划路线。跨恒星运输在“星际时代”研究完成后开放，沿已发现航线自动运行。

运输船携带一批实际矿物；发船时从起点扣除，抵达时加入终点。航行时间和运力在星系图可见，船只动画对应真实运输状态。运输任务在等待期间允许取消并返还未出发的货物。跨银河运输还受中继站吞吐量限制；旧银河可以帮助新银河起步，却不能瞬间替代当地工业。中继站升级提高每分钟运力，银河间距离决定到达时间。

运输界面永远解释当前阻塞原因，例如“矿物够，但下一艘船 24 秒后到”“太空港未建成”“中继站运力已满”。等待应当可预期；玩家总能同时做探索、升级或另一处建设。

## 7. 自动化是玩家获得的新能力

**第一座太空电梯必须在第一恒星系内解锁，目标时间为开始后 35—50 分钟。** 完成后，玩家可以把当前星球保存为蓝图，并在下一颗星球直接应用。蓝图记录建筑的目标数量与升级优先级，不记录必须完全一致的坐标。

自动建设按同样的矿物、信用点、能源和建造时间规则执行，不凭空生成资源。若当前星球矿点较少，系统建到可行上限；若能源不足，先补发电；若缺矿物，自动提出运输请求。界面显示“正在做什么、还差什么、预计何时完成”。玩家可暂停蓝图、调整优先级或随时接管。

自动化分三级，每一级减少一种已经学会的操作：

1. **蓝图建设**：自动放置建筑，让第二颗星球开始有区别于第一颗的体验。
2. **自动升级与运输优先级**：系统按玩家设定的“矿业／科研／商业”目标追赶瓶颈。
3. **星系托管**：玩家只指定星球专长与系统目标，成熟星系继续运行并向新边界供货。

自动化的奖励是把注意力转移到更高尺度。它不应成为一个等待很久才出现的结尾功能。

## 8. 科技和进度

科技树以短主线加少量二选一强化组成。关键功能按确定顺序解锁，不要求玩家猜到隐藏前置条件：

1. **行星工业**：矿机、发电、科研、商业；学会查看回本时间。
2. **轨道时代**：本星系探针、殖民船、太空港；第一次跨星球运输。
3. **自动化时代**：太空电梯、星球蓝图、自动升级。
4. **星际时代**：跨恒星探针、跨恒星殖民、星系托管。
5. **银河时代**：银河中继站、方舟船、跨银河支援。

科技同时消耗科研点与信用点，但不需要额外的“建过三颗星球才能研究”式隐藏门槛。重要里程碑可以有公开的建造要求，并在科技卡上提前显示。研究可排队；费用在研究开始时扣除，完成时解锁，取消时按未完成比例返还。

三个银河的差异应体现在**新决策**，而非只提高价格：

| 阶段 | 主要新问题 | 玩家的新能力 |
| --- | --- | --- |
| 银河 I：Azure Reach | 哪颗星球适合矿业、科研或发电？何时把旧星球交给蓝图？ | 建设、殖民、运输、星球自动化 |
| 银河 II：Crimson Expanse | 中继吞吐有限，哪些资源应由旧银河支援，哪些必须本地生产？ | 跨银河运输配额与星系托管 |
| 银河 III：Abyssal Crown | 多个银河同时生产，哪里投资才能最快完成最终工程？ | 银河级优先级与最终工程 |

银河 I 保留约 8—12 个有意义的恒星系，后两座银河各约 6—10 个。无需殖民全部系统才能通关。已完成银河不会重置，仍可访问、升级并向前线供货。第三银河的最终工程给出清晰结局；通关后解锁无尽边疆，无尽模式不承担主线平衡的责任。

## 9. 目标节奏与验收

以下是**待试玩验证的目标**，不是直接写死在代码中的等待时间：

| 游戏时间 | 预期事件 | 玩家应获得的感受 |
| --- | --- | --- |
| 0—5 分钟 | 第一座矿机、一次产量增长 | 每次操作立刻有反馈 |
| 5—20 分钟 | 能源与矿点形成第一个投资选择 | 看懂瓶颈和取舍 |
| 20—35 分钟 | 第一艘殖民船、第二颗星球 | 地图从“背景”变为机会 |
| 35—50 分钟 | 第一座太空电梯与蓝图 | 原先的手工工作可以交给系统 |
| 1—2 小时 | 第一个成熟星系、跨恒星探索 | 玩家开始管理多个目标 |
| 4—6 小时 | 建成第一座银河中继站 | 第一次尺度跃迁 |
| 12—16 小时 | 完成第三银河最终工程 | 旧版图仍在支援前线 |

节奏不靠长时间空等维持。正常游玩时，下一项有意义的决策应在 30—90 秒内出现；较长运输或研究要能与别处的活动并行。统计试玩中的“无事可做时间”“手动重复次数”“玩家主动查看瓶颈面板次数”和“第二颗星球首次应用蓝图的时间”。

## 10. UI 与表现

左上角显示四项资源及变化率；能源显示当前系统供给／需求，选中其他星系时随视图切换。顶部显示银河 → 星系 → 星球路径。右侧对象面板只展示当前选择的决策信息：产量、费用、能源、专长、运输 ETA 和预计回本时间。底部是建造、科技、蓝图三个入口。

一处全局“**当前瓶颈**”提示指出限制增长的因素，但同时给出至少两种可行解决方式，例如“升级本地矿机：+8/s，约 4 分钟回本”与“殖民邻星：+3 矿点，约 7 分钟建成”。提示可以关闭，不自动替玩家作决定。

矿机钻头、发电核心、太空电梯货舱、真实货运船和逐步点亮的星图构成主要视觉奖励。稀有天体与银河风格增加探索新鲜感；界面始终保持可读，不让装饰遮挡比较信息。提供暂停、1×、2×、4×，切换速度不影响结算正确性。

## 11. 离线与后台模拟

游戏关闭后按实际经过时间结算，原则上给予 **100% 离线生产**。结算遵守相同的能源效率、建造队列、运输容量和科技规则，不把“每秒产量 × 离线时长”直接当作所有资源的最终答案。离线报告按来源列出新增资源、完成的运输与建设，以及尚未完成的任务；玩家可核对结果。

当前星球才实例化建筑节点；其他星球保存建筑状态与产能摘要。后台以事件推进建筑完成、运输抵达和科技解锁，其余时间段用解析式累计产量。保存文件记录时间戳、队列、船只、库存和已解锁内容；版本升级时有迁移字段。巨大数值使用统一数值表示与格式化层，避免浮点累计和 UI 显示不一致。

## 12. 第一可玩版本：先证明循环

**范围**：一个恒星系、三颗星球、八种核心建筑、四种资源、一次探针探索、两次殖民、真实运输、一座太空电梯、一个可保存和应用的蓝图。目标游玩时长 60—90 分钟。银河切换、方舟、稀有天体和无尽模式在这个版本之后开发。

**通过标准**：

- 新玩家无需文字墙，能在 5 分钟内建第一座矿机并理解产量变化。
- 在前 20 分钟，至少出现一次玩家能解释的“升级旧矿点还是开发新矿点”选择。
- 玩家在第二或第三颗星球能应用蓝图，明显少做重复操作，并看见自动化遵守资源规则。
- 运输船的出发、抵达、库存变化与界面 ETA 一致。
- 任意时刻都能从 UI 理解为何建筑停工、运输等待或能源不足。
- 保存、读取、加速和离线结算不会凭空生成或丢失资源。

若这一小时不好玩，不靠增加银河数量来补救。先调整建设反馈、瓶颈信息、自动化时机与投资回报，再扩充内容。

## 13. 明确暂不加入的系统

首个正式版本不加入人口、食物、传送带吞吐、生产配方、矿点枯竭、建筑维护费、复杂仓储、天气、昼夜、手控舰队、外交、海盗袭击或硬性宜居门槛。这些机制会把注意力从“发现瓶颈 → 扩张 → 自动化”转向持续维护。后续若加入新系统，必须证明它创造了新的有趣决策，并能被自动化接管。

---

**设计底线**：玩家不需要反复证明自己会放矿机。每当他掌握一个尺度，游戏就把这个尺度交给系统，让他决定下一片版图如何发展。
